# Duckpond: runtime audit and rebuild direction

Investigated 2026-09-20. This is a proposal and observed baseline, not a claim that the rebuild is implemented.

## Observed failures

- AMD gfx1201 GPU: PyTorch reports 16,304 MB VRAM; host has approximately 64 GB RAM. ROCm 7.1 and torch 2.10 detect the GPU. Media environment has Diffusers 0.40.0. Model storage has approximately 680 GB free.
- `image-gen-bridge-8765.service` existed but was disabled and stopped. Enabled and started it; `/health` now responds successfully. This restores discovery, not generation readiness.
- No ready image or video models reported by the bridge. SDXL lacks UNet/VAE weights. LTX 0.9.7 lacks its encoder, tokenizer, transformer and VAE. GGUF media needs dedicated loaders and companion components.
- The MiniMax H3 cache directory inspected contains repository metadata, not installed model weights. Its name was also missing from both model classifiers. Added H3 video classification, with tests ensuring MiniMax M3 remains a chat model and H3 GGUF stays unavailable without its loader.
- SearxNG on port 8888 returned 20 results for a diagnostic query. Search infrastructure works; agent use and citation quality still require end-to-end evaluation.
- Coding tools already include file reading/writing/editing, shell, web search and screenshots. The agent prompt explicitly prohibits dev servers and requires static HTML/CSS/JS. The port preview route is disabled. These decisions limit app building independently of model quality.
- The default sandbox is an unpinned Python/Node image. Screenshot support depends on Chromium being installed. A reproducible runtime and browser verification are needed.
- Existing worktree contains substantial staged and unstaged user work. Preserve it while implementing the redesign in reviewable slices.

## Product direction

Use three primary destinations: Workspace, Media, Models. Put providers, usage, themes and advanced configuration in Settings. Keep the duck as a restrained identity element. Use typography, spacing and a single accent to establish hierarchy; reduce nested cards, badges and competing controls.

Workspace: project/history navigation at left, conversation in the main pane, resizable artifact pane with Preview / Files / Changes. Keep task progress in one expandable activity stream with visible errors and Stop. Preserve the active project and preview between turns. On mobile show one pane at a time with an explicit switcher.

Media: prompt and input references beside a large output canvas; gallery beneath or in a secondary pane. Only show controls supported by the selected model. Preserve seed, prompt, model revision, dimensions and generation settings with each artifact. Separate waiting for GPU, loading, sampling and encoding progress.

Models: compact inventory and discovery results with a detail pane. Show task, runtime compatibility, complete disk cost, estimated VRAM/RAM, license and installation status before download. Distinguish downloaded files from a runnable installation. Offer Resume, Install missing components, Configure runtime and Test as appropriate. Show measured generation latency separately from estimates.

## Implementation order and acceptance criteria

1. **Reliable media runtime.** Separate media dependencies from the Unsloth application environment. Define model-specific installation manifests covering all encoders, VAEs and weight shards. Add runtime diagnostics, persistent jobs/cancellation and GPU scheduling shared with chat. Pass a real prompt through Duckpond to a saved image, repeat after service restart, and verify cancellation. Integrate video separately with a real playable output including audio when supported.
2. **Coding workspace.** Add supervised dev-server processes and authenticated preview routing with WebSocket support and isolation from app credentials. Then update the static-only prompt. Pin a sandbox with browser tooling. Acceptance: create and edit a small Vite application, install dependencies, run tests, show its live preview, verify a screenshot, and reconnect without losing the run.
3. **Search experience.** Make search activity, sources and failures visible in the same run stream. Evaluate actual tool invocation, page reading, source attribution and a failed-search recovery path. Successful SearxNG connectivity alone is not enough.
4. **Model installation UX.** Track download -> component verification -> runtime compatibility -> smoke test -> ready. Expose repair actions. Test partial download, missing companion, unsupported GGUF, restart/resume and insufficient memory cases. Never claim “fits” using checkpoint bytes alone.
5. **Interface consolidation.** Implement the agreed workspace direction and Media/Models layouts. Validate with real workflows at desktop and phone widths; mocked screenshots cannot prove model generation or coding execution.
