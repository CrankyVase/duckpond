# Duckpond backend and workspace checkpoint

The active priority list is [../.todo](../.todo). This pass preserves the main
chat layout and existing local work while repairing media contracts and replacing
the Media Studio workspace. Model execution is explicitly deferred by the user.

## Implemented

- Metadata-only media discovery checks model architecture, task, runtime and local
  weight completeness. Explicit selection fails with a reason instead of changing
  tasks/models. Unsupported GGUF media and incomplete downloads stay visible.
- Diffusers dispatch uses the declared pipeline; duration, sample rate, seed 0,
  cancellation, device placement and model reuse have targeted fixes. Standard
  MusicGen and optional OmniVoice have dedicated adapters. Native audio no longer
  receives nonexistent cloning arguments.
- Speech voice choices include ready local models. Local selection does not fall
  back to a paid provider. Audio files and speech caches retain correct formats.
- Hugging Face avatars are bounded server-fetched raster bytes, including redirect
  validation. Hub READMEs discard active HTML and automatic remote images. MapLibre
  resource requests now pass through an authenticated, host-restricted proxy.
- Media Studio separates task controls and model readiness, keeps a saved gallery,
  and exposes Stop and inline errors. Hub has simpler navigation, quieter filters,
  an initialization fix and protection against stale search results.
- Initial context estimates precede generation; llama timing events supply prompt
  counts during decoding. Reconnect snapshots retain counts. Stale count requests
  cannot overwrite another conversation or an active stream. Message render errors
  fall back to that message's plain text without replacing the whole chat view.
- Inline HTML code previews run without app-origin access. Multi-file workspace
  previews still need a separate-origin architecture; this is tracked explicitly.

## Validation without models

Run `npm test` in server; `npm run test:media` in server; `npm test` and
`npm run build` in web. Python tests create synthetic caches and stub ML imports.
They do not load weights. Browser smoke tests intercept every API and reject
requests outside the preview origin:

```
cd web
npm run build
npm exec vite preview -- --host 127.0.0.1 --port 5198
# In a second shell, with Playwright installed in your test environment:
node test/browser-smoke.mjs
```

The browser script also accepts PLAYWRIGHT_MODULE (package name or absolute module
path), CHROMIUM_EXECUTABLE and PREVIEW_URL. Screenshots go to /tmp. It does not use
live inference endpoints. Production builds retain existing accessibility/large
chunk warnings, which remain on the polish backlog.

Checkpoint results: server suites passed, 19 synthetic Python tests passed, web
README tests passed, production build passed. Desktop/mobile browser checks passed
for Media/Hub, Stop/errors, task selection, message-render failure recovery and
inline preview origin isolation. No models were loaded or run by these checks.

## Known limitations and next work

The local scan found incomplete SDXL/LTX components, an unsupported Krea GGUF media
loader, and OmniVoice weights without the OmniVoice Python runtime. Installing
adapters, downloading components, actual synthesis/cloning checks and performance
benchmarks were not performed. Model reuse/inference mode are code improvements;
there are no measured speedup claims and no reduced context settings.

User reports also include timeouts, hardcoded limits interrupting useful work,
non-updating context, intermittent HTML preview failures, lost visible history on
errors, and cluttered agent coding/tool displays. These are prioritized in .todo.
The small recovery changes here do not establish that all those reports are fixed.
Existing agent limits and remote output ceilings still need a deliberate audit.
Cloudflare operational notes remain outside the repository because they contain
credentials. No Cloudflare configuration changes were made.

This checkpoint archives source, not databases, credentials, generated media or
model weights. Python bytecode is ignored. The running media bridge needs a service
restart to pick up changes; deployment timing and hardware tests are separate from
source verification.

## Deployment reliability follow-up

The old timer compared mtimes under all of web/server, including generated output,
then restarted unconditionally. The replacement fingerprints only runtime source
and package files. It ignores databases, images, Python caches and Vite output;
content changes and tracked deletions trigger deployment, touching a file does not.
Package installs only occur when package metadata changes. A lock prevents timers
from overlapping, and source fingerprints advance only after successful health.

A local .deploy-drain marker stops admitting API work during the restart window.
Already-admitted handlers finish, detached agent runs and downloads keep the guard
busy, and embedding backfills are tracked/paused. Stop, approval and live-tail
controls stay available. If work is still active after the short drain window,
the deployer removes the marker and retries on its next tick. A stale marker expires
so a killed deployer cannot lock out the UI permanently. There is no inference
runtime deadline or context change here.

The first controlled restart must load the new health/guard implementation. Until
then, the deploy script treats an older health response as unsupported and defers;
it never guesses that an old process is idle. No live services were restarted for
this change, consistent with deferred model execution (server startup can schedule
embedding backfill). Bridge source changes now also trigger a bridge restart at
an idle deployment. Configure DUCKPOND_DEPLOY_HEALTH if the service is not on port
3000; DUCKPOND_REPO and DUCKPOND_NODE_BIN override the local install paths.

Regression tests use Fastify injection and a temporary Git tree, without live
services. They cover active requests, drain admission, control endpoints, detached
activity, background work, stale markers, generated-output exclusion, content
hashing, dependency hashes and file deletion. Durable job checkpoints across
unexpected process crashes remain future work.

Full deploy-script tests also passed with fake npm, curl and systemctl commands:
legacy/busy deferral, successful idle restart, no restart for generated output,
failed-restart cleanup and retry, and no dependency reinstall for source-only edits.
